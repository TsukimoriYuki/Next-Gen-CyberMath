# 共通テスト型模試 品質方針

Cyber Math の本番演習は、通常ドリルの延長ではなく「問題冊子を読み、マーク欄に解答し、提出後に復習する」体験へ近づける。

## 目的

- 共通テスト数学IA・数学II/B/Cの本番形式に近い時間制約と情報量を再現する。
- 公式過去問や実在模試の転載は行わず、完全オリジナルの問題として制作する。
- 正答だけでなく、誘導文、図表、会話文、データ読み取り、時間配分を含めて測定する。
- 試験中は実力測定、提出後は復習と弱点回収に役割を分ける。

## 問題冊子形式にする理由

通常ドリルのカードUIでは、問題文、ヒント、解説、関連講義が近くに並びやすい。共通テスト型模試では、受験生が冊子を読み、必要な情報を探し、別のマークシートへ解答する流れを再現する必要がある。

初期実装では PDF をページ画像化して表示する方式を採用する。見た目が安定し、mobile でも制御しやすい。将来的には pdf.js とテキストレイヤーを検討する。

## 過去問を転載しない方針

- 公式過去問の本文、図、設問、選択肢をコピーしない。
- 実在模試の紙面、ロゴ、デザインを模倣しない。
- 形式、制限時間、誘導の作り方は参考にしてよいが、題材・数値・文面は Cyber Math 独自にする。
- サンプル冊子には `Cyber Math 共通テスト型模試` と明記し、公式試験と誤認されないようにする。

## 問題数・小問数・マーク数を分ける

共通テスト数学では、1つの小問に複数のマーク欄がある。したがって、UIと採点では次を分ける。

- `questionCount`: 問題冊子上の小問数
- `answerSlotCount`: ア・イ・ウなどのマーク欄数
- `sectionCount`: 大問数
- `score`: マーク欄または設問に割り当てる配点

表示例は `6小問 / 24マーク` のようにする。採点は小問数ではなく `answerSlots` を基準に行う。

## 試験中に表示しないもの

試験中モードでは、次を出さない。

- ヒント
- 解説
- 正誤即時表示
- 関連講義
- 判別フロー
- 難易度タグ
- この問題の核
- 身につく武器
- ミス別補講
- 復習導線
- 答えが推測できるタグ

試験中に表示してよいものは、問題冊子、解答欄、残り時間、見直しフラグ、提出ボタン、ページ送り、拡大縮小だけを基本とする。

## 提出後に表示するもの

提出後の復習モードでは、次を表示してよい。

- 正答
- スロット単位の正誤
- 大問別得点
- 解説
- ヒント
- 関連講義
- 復習導線
- ミス別補講
- 弱点分析

提出前と提出後で UI の役割を明確に分ける。

## 数学IAの構成目安

- 第1問: 数と式、集合と命題、図形と計量
- 第2問: 二次関数、データの分析
- 第3問: 図形の性質
- 第4問: 場合の数と確率

70分で全問を解き切るには余裕がない設計にする。簡単な公式代入だけで終わらせず、表、図、会話文、条件変更を組み合わせる。

## 数学IA 70分模試 第1回

`/common-test/simulator/math-1a-paper-001` は、冊子型フル模試の初回として次の条件を満たす。

- 4大問、22小問、56マーク、100点、70分で構成する。
- 問題冊子は `public/exam-papers/math-1a-paper-001/` の7ページSVG画像で表示する。
- 第1問は数と式、集合と命題、図形と計量を扱い、面積から高さ、三角比、内接円半径、外接円半径の判別を入れる。
- 第2問は二次関数とデータの分析を扱い、頂点、端点、表、散布図、外挿判断を入れる。
- 第3問は図形の性質を扱い、内心・外心・重心、角の二等分線、中線、補助線選択を入れる。
- 第4問は場合の数と確率を扱い、同じものを含む順列、余事象、条件付き確率、独立と排反の判断を入れる。
- 提出前は冊子、マーク欄、残り時間、見直しフラグだけを表示する。
- 提出後は総得点、大問別得点、正答マーク数、未入力リスト、フラグリスト、正答、解説、関連講義を表示する。
- 公式試験・公式過去問・実在模試の転載ではないことを表紙と品質方針に明記する。

このフル模試は、既存のWeb大問演習とは別系統の「新形式：冊子型」として扱う。既存の `CommonTestExamPreset` ベースの演習は、演習量確保と弱点確認のための「旧形式：Web大問演習」と位置付ける。

### 第1回レビュー結果

2026-06-30 の品質レビューで、冊子画像7ページと `answerSlots` を照合した。冊子内の56マークはすべて `answerSlots` に存在し、重複はない。配点は第1問30点、第2問30点、第3問20点、第4問20点、合計100点である。

全問検算の結果、初期版では本文が抽象的で正答を一意に決めにくい箇所があったため、冊子本文を解ける設問へ修正した。第1問は根号計算、集合、面積から高さ、三角比、内接円・外接円半径、空間断面判別を扱う。第2問は軸・端点・定義域とデータ分析を扱う。第3問は中心判別、角の二等分線、中線、補助線選択を扱う。第4問は同じものを含む順列、余事象、条件付き確率、独立と排反を扱う。

想定平均点は60点前後。第1問前半と第4問前半で基礎得点を作り、第2問後半・第3問後半・第4問条件付き確率で差がつく設計とした。外部レビューでは、第3問にチェバ・メネラウスをさらに絡めるべきか、第1問の文章量をもう少し増やすべきかを確認する。

詳細な検算記録は `docs/math-1a-paper-001-review.md` に残す。

## 数学II・B・Cの構成目安

- 第1問から第3問: 必答
- 第4問から第7問: 3問選択

必答と選択の区別をデータ構造に持たせる。選択制では、解答欄数と採点対象を選択した大問に応じて変える。

## 難易度目標

- 簡単すぎない。
- 平均点55から65点程度を目安にする。
- 誘導文、図表、会話文を増やす。
- 前半は取りやすく、後半で条件読み替えや計算量が増える構成にする。
- 70分で時間が足りなくなる設計にする。
- 計算だけでなく、モデルの限界、条件外の判断、選択肢消去を入れる。

## データ構造方針

`ExamPaper` は冊子単位、`ExamPaperSection` は大問単位、`ExamAnswerSlot` はマーク欄単位を表す。

```ts
export type ExamPaper = {
  id: string
  title: string
  subject: "math1a" | "math2bc" | "private-mid"
  durationMin: number
  totalScore: number
  questionCount: number
  paperPdfUrl?: string
  pageImages?: string[]
  sections: ExamPaperSection[]
  answerSlots: ExamAnswerSlot[]
}
```

```ts
export type ExamAnswerSlot = {
  id: string
  label: string
  sectionId: string
  groupLabel?: string
  type: "digit" | "signedDigit" | "choice" | "symbol" | "decimal" | "fractionPart"
  choices: string[]
  correctAnswer: string
  score: number
}
```

```ts
export type ExamPaperSection = {
  id: string
  title: string
  pageStart?: number
  pageEnd?: number
  score: number
  questionCount: number
  answerSlotIds: string[]
}
```

## 現状調査メモ

- 既存の70分演習は `CommonTestDrillQuestion[]` をもとに、1小問1レコードで表示している。
- 解答欄数は `activeQuestions.length` に近く、共通テスト数学のア・イ・ウ単位ではない。
- 第1回数学IAは `limitMathIaExamQuestions` により4大問×4小問へ絞られ、約16問になる。
- 第2回・第3回は `common-test-exam-sets.ts` の大問別小問を使うため、こちらも小問数ベースである。
- 既存の試験中画面には、共有ステム、難易度バッジ、手応え記録、マーク入力補助が残っていた。
- 今回、試験中画面から難易度・手応え・青い補助ステムを外し、サンプル冊子型演習では `answerSlots` からマーク欄を生成する。

## 今後の拡張

- 数学IAフル模試では各大問にページ画像と `answerSlots` を持たせる。
- 数学II・B・Cでは必答・選択大問の採点対象切替を `ExamPaper` 側へ持たせる。
- PDF生成パイプラインを用意し、同じ原稿から PDF とページ画像を出力する。
- 画像方式のアクセシビリティ補助として、ページごとの要約テキストを別途持たせる。
