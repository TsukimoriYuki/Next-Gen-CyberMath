# 講座品質基準 — CYBER OS Course Quality Guidelines

このドキュメントは、今後 Phase 20 以降で講座本文を増やすときの品質基準を明文化したものです。
ここに記した基準を守ることで、初学者が躓かず、上級者が満足できる高品質な講座を維持します。

---

## 共通ルール（全レベル共通）

### 数式の書き方
- インライン数式は `$...$` のみ使う（display math delimiter は **禁止**）
- 複数行の数式は改行 + インライン数式を使うか、plain text で段落として書く
- TeX のバックスラッシュエスケープは `String.raw` または二重バックスラッシュ `\\` で書く

### 著作権
- 大学過去問の問題文をそのままコピーすることは **禁止**
- 過去問を参考にした問題は「過去問風オリジナル問題」として扱い、本文を再構成する
- 「〇〇大学 〇〇年度 大問〇」などの出典を書く場合は、独自の言い回しで問題を再構成すること

### 長さ・密度
- 1 講座（`CourseLesson`）は 10〜40 分程度を目安とする
- レッスンブロックは 5〜10 個が目安（多すぎると集中が切れる）
- 1 ブロックの `body` は 200 文字以内を目安とする（長い場合は分割する）

## 初学者講座（level: "beginner"）

対象：その単元を初めて学ぶ、または授業で習ったが定着していない人。

### 必須事項
- [ ] **途中式を飛ばさない**：計算の各ステップを明示する
- [ ] **公式の意味を説明する**：公式を与えるだけでなく、なぜその形になるかを示す
- [ ] **最初の例題は簡単なものから**：$a=1, b=0$ の最もシンプルなケースから始める
- [ ] **専門用語は初出で説明する**：「平方完成」など初出の用語は必ず一文で定義する
- [ ] **よくあるミスブロックを入れる**：初学者が詰まりやすい箇所を先回りして説明する
- [ ] **確認問題を 1〜3 問入れる**：解答とヒントも必ず付ける
- [ ] **次のステップへの誘導**：講座末尾に「次はこちら」を書く

### 禁止事項
- 「〜は明らか」「自明より」などの表現
- 暗記を促すだけで意味の説明がない
- 難しい応用例を先に出す

### チェックリスト
- 初めて見る人がこの講座だけで理解できるか？
- 「なぜ？」という問いに、この講座の中で答えているか？
- 確認問題の難易度は学んだ内容をそのまま使えばできるか？

## 中級者講座（level: "standard"）

対象：一通り学んだが、試験で安定して得点できない人。典型解法と判断基準を整理したい人。

### 必須事項
- [ ] **典型解法のパターンを明示する**：「こういう問題はこの手順で解く」を箇条書きで示す
- [ ] **場合分けの判断基準を書く**：「何を見て場合分けするか」の基準を先に示す
- [ ] **よくあるミスブロックを入れる**：中級者がケアレスミスをする箇所を具体的に示す
- [ ] **例題は定番・典型のものを使う**：教科書レベルの典型問題を丁寧に解く
- [ ] **確認問題を入れる**：少し応用を加えた問題で、自力で解けるか確認させる

### 禁止事項
- 初学者と同じ内容を繰り返すだけ（知識の整理にならない）
- 難問を突然出す

### チェックリスト
- 一周した人が「そういうことか！」と腑に落ちる説明になっているか？
- 解法の選択肢と判断基準が明確か？
- 試験でこの単元が出たとき、この講座を読んで対処できるか？

---

## 上級者講座（level: "advanced"）

対象：標準問題は解けるが、誘導なし・複合問題・難問で詰まる人。

### 必須事項
- [ ] **問題の構造を分析する視点を教える**：「何を問われているか」の整理方法を示す
- [ ] **複数の解法を比較する**（可能なら）：どの解法が効率的か判断する眼を育てる
- [ ] **「なぜこのアプローチを選ぶか」を言語化する**：直感的な選択を言語化して再現可能にする
- [ ] **過去問風オリジナル問題を使う**：大学過去問の本文コピーは禁止。独自に再構成した問題を使う
- [ ] **解答の精度・表現にこだわる**：答案として書くべき記述レベルを示す

### 禁止事項
- **大学過去問の問題文をそのままコピーすること**（著作権上の理由）
- 解法を列挙するだけで選択基準を示さない

### チェックリスト
- 誘導なしで解ける実力がつくか？
- 「見たことのない問題でも対処できる汎用性」があるか？
- 答案として書くべき記述の粒度が示されているか？

## レッスンブロックの使い方

| ブロック種別 | 使う場面 |
|---|---|
| `intro` | 講座の導入。なぜ学ぶかを1〜2文で示す |
| `concept` | 概念・定義の説明。用語と意味をセットで |
| `formula` | 公式の提示。導出も短く添える |
| `workedExample` | 例題。途中式を省かず書く |
| `commonMistake` | よくあるミス。「ミスの内容」と「正しい考え方」をセットで |
| `strategy` | 解法戦略・判断基準。「こういうときはこう」の形で |
| `practice` | 確認問題。難易度は学んだ内容をそのまま適用できるレベル |
| `summary` | まとめ。箇条書きで要点のみ |
| `nextStep` | 次の講座・演習への誘導 |

---

## 品質タグ（`qualityTags`）の使い方

以下のタグを `qualityTags` 配列に付けることで、品質レビュー時に確認漏れを防ぐ。

- `途中式あり` — 計算の途中式が省略なく書かれている
- `よくあるミスあり` — `commonMistake` ブロックが含まれている
- `確認問題N問` — 確認問題の数を記録（例: `確認問題2問`）
- `場合分け` — 場合分けの判断基準が明示されている
- `入試標準` — 入試標準レベルの問題を含む
- `過去問風オリジナル` — 過去問を再構成したオリジナル問題を使用
- `Phase20補完予定` — 現時点で内容が仮であり Phase 20 以降で充実させる予定

---

## レビューの流れ

1. `qualityTags` の内容と `lessonBlocks` の内容が一致しているか確認
2. `checkQuestions` に `answer` と `hint` が付いているか確認
3. 数式に display math delimiter が含まれていないか確認（`$...$` のみ許可）
4. 大学過去問の文言がそのまま含まれていないか確認
5. 初学者講座：途中式が省略されていないか確認
6. 上級者講座：過去問本文コピーがないか確認
